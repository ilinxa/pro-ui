# Structure audit — news-card v0.4.0 (2026-08-11)

verdict: findings-logged
artifact: 178.6 KB / budget not declared in meta.ts (see Owners)

## 1. Compound compliance (.claude/rules/compound-component-structure.md)

`news-card` doesn't strongly trigger the rule's own conditions: no heavy npm dep (`lucide-react`
only), and the "5 variants" are mutually-exclusive alternate renderings of one card, not stackable
regions a consumer would combine. What sub-part surface it does have (`NewsBadges`, `StatusBadge`,
`VisibilityBadge`, `SponsorBadge`, `LiveUpdateLine`, `NewsAuthorByline`, `NewsPublisherRow`,
`NewsPaywallGate`, `ContentSensitiveGate`, `QuotedArticleCard`, `NewsEngagementCounts`, `NewsKebab`)
is already flat-exported from `index.ts:51-62`. The cross-procomp `comment-thread` dependency
(`meta.ts` `dependencies.internal`) is exclusively a **type-only** import (`CommentMenuItem`, used in
`types.ts:6`, `lib/defaults.tsx:29`, `parts/news-kebab.tsx:14` — all `import type`) with zero runtime
weight, so it doesn't trigger the "composes another procomp" heavy-dep concern either. No findings.

## 2. Dead / orphaned public API

**Finding:** `openKebab()` — one of the 11 imperative-handle methods `meta.ts:53` advertises as
shipped ("v0.3.0 — 11-method imperative handle: openKebab / triggerEdit / ...") — is a literal
no-op in the implementation (`news-card.tsx:288-295`):

```
openKebab: () => {
  // Variant parts own the actual trigger ref. Handle the open via a
  // sentinel — variant parts subscribe via the kebab trigger they
  // render. v0.3 ships an open-emitter at C11; for now the handle
  // method is wired but the trigger is per-variant.
  // No-op until C11 wires the per-variant open ref.
},
```

Grepping the whole folder for `openKebab` turns up exactly three hits: the type declaration
(`types.ts:639`), the meta claim, and this stub — there is no emitter/ref wiring anywhere else in
the folder. A consumer calling `ref.current.openKebab()` gets nothing, despite the method being
publicly typed and advertised as shipped. This is a self-documented incomplete implementation, not
a speculative finding.

## 3. Undocumented prop semantics

The entire imperative handle (all 11 methods — `openKebab` / `triggerEdit` / `triggerDelete` /
`triggerPublish` / `triggerUnpublish` / `triggerPin` / `triggerFeature` / `revealPaywall` /
`revealSensitive` / `reset` / `getCurrentItem`) has **zero** coverage in `usage.tsx` — there is no
"Imperative handle" section at all, unlike every sibling data-family component in this audit batch
(`card-tree`, `task-tree`, `gantt-timeline` all document theirs). A consumer has no in-docs path to
discover the handle exists.

## 4. A11y baseline

Mostly solid and matches the `meta.ts` claim (`h-11` / 44px reveal buttons in `NewsPaywallGate`,
real `<button>` elements with `aria-label`/`focus-visible` rings throughout). **One finding:**
`ContentSensitiveGate`'s `compact` mode (used by the `small` variant's 96×96 thumb,
`parts/content-sensitive-gate.tsx:82-97`) intentionally drops the 44×44 target size — its own doc
comment says so directly ("Drops the heading + warnings list and shrinks... in favor of a... tiny
`<button>` pill"). That's a reasonable, deliberate tradeoff for a genuinely tiny container, but
`meta.ts:60`'s blanket claim — *"WCAG 2.5.5 — all interactive elements ≥44×44"* — doesn't carve out
this documented exception, so the claim over-generalizes.

## 5. Weight & slice candidacy

Core folder (excl. `demo.tsx`/`dummy-data.ts`/`usage.tsx`/`meta.ts`): **4,521 LOC**. Top-3 files:
`types.ts` 829 (18.3%), `lib/defaults.tsx` 441 (9.8%), `news-card.tsx` 378 (8.4%).

The 5 variant parts (`parts/featured.tsx` 314 + `parts/large.tsx` 281 + `parts/medium.tsx` 330 +
`parts/small.tsx` 148 + `parts/list.tsx` 268 = **1,341 LOC, 29.7%**) are all imported statically in
`news-card.tsx:16-20` and switched on at render (`:383-395`), so every consumer bundles all 5 even
though `variant` is typically fixed per call-site (a feed uses `medium` everywhere; a hero section
uses `featured` once). Base-coupling is genuinely low — the variant parts don't cross-import each
other. This doesn't map cleanly to the P3 injection-surface convention (that's built for opt-in
*capabilities*, not mutually-exclusive *display variants* selected by a runtime prop) — the more
natural fix, if pursued, is per-variant `React.lazy` + `Suspense` rather than a formal
`news-card-<variant>` feature-item split. Noting as an observation, not a slice-candidate
recommendation on the P3 model.
