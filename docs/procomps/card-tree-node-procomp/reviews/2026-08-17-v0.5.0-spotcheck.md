**Falsification.** The 13-check test file was written and run **before** the fix: **7 failed, 5
passed**. The 5 passes are the no-regression anchors, so the file was demonstrably not just broken.
After the fix, 13/13. This is the project's standing bar — green that was never seen red proves
nothing — and it is the reason FU-A was deferred rather than guessed at in v0.4.0.

## Findings

| # | Severity | Finding | Verdict |
|---|---|---|---|
| F-1 | 🔹 Low | `RESERVED_KEYS` is exactly `__rcid`/`__rcorder`/`__rcmeta`, but the retired heuristic skipped **any** `__rc`-prefixed key, so `__rcfoo: {...}` is now walkable. | **CONFIRMED — accepted.** The same widening `enumerateSubcards` took at v0.4.0; the walker now agrees with the viewer, which is the whole point. Pinned by a test, documented in guide §10.3. |
| F-2 | 🔸 Medium | Not purely additive: with **default** options a built-in block payload carrying `__rcid` stops resolving. | **CONFIRMED — accepted + documented.** The old behaviour was the bug. Shape is pathological (`<CardTree>` attaches `__rcid` to cards, never to block payloads). Stated in guide §7.7 under its own heading rather than buried in "additive". |
| F-3 | 🔹 Low | `findCardPath` has no cycle guard, and the wider predicate follows more paths. | **DROPPED — pre-existing.** The old heuristic followed cycles too; `node.data` is JSON by contract. Noted, not fixed. |
| F-4 | 🔹 Low | An inline `customPredefinedKeys` literal re-runs the walk each render. | **CONFIRMED — mitigated.** No state is set, so no loop (unlike card-tree v0.6.0's). Module-scope defaults keep the zero-config path stable; documented on the prop. |
| F-5 | ⚠️ High | `demo.tsx` passed the registrations to `<CardTree>` — with a comment stating "without this the two surfaces would disagree" — while the `<PortEditorStrip>` three lines above got nothing. | **CONFIRMED — fixed.** The documentation was already right; the code beside it was not. |

**Rigor note.** The ladder asks for one fresh finder subagent. None was spawned (subagent
orchestration was not requested this session). The compensating measure was to write each
hypothesis as an explicit falsification attempt and check it against source or a run rather than
reasoning from the diff: F-1 came from reading `RESERVED_KEYS` instead of trusting the comment,
F-5 from re-reading the demo. Two of five findings were produced that way and both changed the
ship. Recorded so this review's provenance is not overstated — a self-review that found things is
still a self-review.

## Notes for the next reader

- **Why FU-A survived two minors.** The divergence is unreachable through the demo's click flow —
  the viewer only makes depth-1 `__rcid`-bearing subcards clickable, exactly the cases both
  walkers agreed on. Consumers who compute `subPath` from a tree outline,
  `CardTreeHandle.focusCard`, or a deep link are the ones it bit. **The regression guard for this
  class has to be the test tier; the demo structurally cannot see it.**
- **`isCardLike` is now gone from this component entirely.** If it reappears, that is a
  regression, not a shortcut.
- **Harness finding (not a product defect):** the consumer smoke initially showed 26 errors from
  7 orphan files left by an event-calendar install predating the P3 feature split. `shadcn add`
  never removes files an item stopped shipping. See the loop doc's U5 section.
