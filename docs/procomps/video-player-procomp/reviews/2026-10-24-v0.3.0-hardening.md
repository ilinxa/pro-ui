### Rotating dimension

- **Chosen:** hydration and real-media behaviour that jsdom cannot show.
- **Why:** jsdom has no media pipeline: events fire only when a test dispatches them, so "the element did something
  before React attached" cannot fail there.
- **Verified?** yes — and it found a real bug: the production browser run showed `0:00 of 0:00` on the server-rendered
  Default tab. A server-rendered `<video>` loads metadata (or fails) before hydration attaches React's handlers, so
  the duration was never known (disabled seek bar) and an early error would never reach `onMediaError`. Fixed by
  reading the element once on mount (`use-video-state.ts`), with regression tests that stub `readyState` / `error`
  before mount (falsified). The same run found two layout defects the unit tests could not see (media-carousel's
  indicator dots on top of the new seek bar; the mute button drawn over the error overlay) — both fixed, tested,
  falsified, and re-observed (49/49, screenshots read).

## Findings (residual, at GATE 3)

The 13 U4 rows and the test author's T1 are closed in the loop file (all CONFIRMED; 12 fixed, F13 documented as not
fixable inside the player). The rows below remain true **after** the fixes.

#### R-01 — Browser proof lives in the session scratchpad

- **Severity:** 🔸 · **Dimension:** 12
- **Observed:** the 49-check Playwright run (`vp-u5-browser.mjs`) is not in the repo, like media-carousel's (its R-01).
- **Suggested fix:** a `tests/e2e` spec for the video-player + media-carousel pages, folded into the e2e follow-up the
  two previous loops already own.

#### R-02 — Real touch devices not exercised

- **Severity:** 🔸 · **Dimension:** runtime
- **Observed:** tap-to-wake, the deferred single tap (300 ms, then `play()` from a timer — inside the browsers'
  transient user-activation window) and seek-bar dragging were driven by mouse and jsdom only.
- **Suggested fix:** the platform's device check (iOS Safari: `webkitEnterFullscreen`, unmuted play after the
  deferred tap).

#### R-03 — Escape in the captions menu inside a Radix Dialog closes the dialog (U4 F13)

- **Severity:** 🔹 · **Dimension:** a11y
- **Observed:** Radix listens for Escape on the document before the menu sees it (media-library's lightbox). Documented.
- **Suggested fix:** none inside the player; a host can stop the dialog's `onEscapeKeyDown` while a menu is open.

#### R-04 — A host `src` change while a refresh is pending is treated as the refresh

- **Severity:** 🔹 · **Dimension:** behaviour
- **Observed:** to support media-carousel's echo (it writes the refreshed URL into `src` before the player's answer),
  any `src` that arrives while `onMediaError` is pending resumes at the old time. A host that swaps to unrelated media
  in that window gets the old position.
- **Suggested fix:** an optional `resumeKey` (item identity) if a consumer hits it.

#### R-05 — RTL time text order

- **Severity:** 🔹 · **Dimension:** i18n
- **Observed:** under RTL the default `timeDisplay` renders right-to-left ("0:10 / 0:00" visually = elapsed first for
  an RTL reader). Correct bidi, but some players force LTR for time. `labels.timeDisplay` can isolate it.

#### R-06 — Size

- **Severity:** 🔹 · **Dimension:** 9
- **Observed:** 83.79 KB of a 90 KB budget (7 % headroom). The flat parts are separate modules, so a consumer using
  `renderControls` with a subset still ships the whole folder (shadcn vendoring) but bundles only what it imports.
