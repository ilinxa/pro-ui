## Findings

#### F-01 — CLI 3.8.5 aborts `story-viewer-fixtures` added after the base (carried from 0.5.4)

- **Severity:** 🔸
- **Dimension:** 9
- **Observed:** unchanged in 0.6.0 (pre-existing; reproduced with 0.5.3). The guide documents the workaround (add the
  fixtures item alone, or both in one command). Root cause still open.

#### F-02 — controlled `pauseReasons`: a host update landing in a later task can drop a same-window add

- **Severity:** 🔹
- **Dimension:** behaviour
- **Observed:** U4-16. The base list rolls back to the prop on a microtask; a host whose `setState` lands later leaves
  a window where a second add computes from the stale list. Narrow; the fix touches same-task compounding.

#### F-03 — demo shows absolute dates

- **Severity:** 🔹
- **Dimension:** docs / demo
- **Observed:** B-8. The fixtures' fixed `NOW` keeps tests deterministic but the demo never shows the relative time.

#### F-04 — owner-mode paging states are unit-tested only

- **Severity:** 🔹
- **Dimension:** demo
- **Observed:** the demo always returns one page; load-more, empty and Retry, and the thousands format, are covered by
  `viewers-engagement-0-6-0` but cannot be exercised from the docs site.

#### F-05 — Tab at machine speed skips the heart toggle

- **Severity:** 🔹
- **Dimension:** a11y
- **Observed:** re-verify F1 — with Tab keystrokes 0 ms apart, Reply → the dialog container, skipping "Show reactions";
  at 40 ms spacing (and at human speed) it is always reached. Likely the reply box's focus pause re-rendering under the
  wrap handler.

#### F-06 — a long header badge squeezes the username at phone width

- **Severity:** 🔹
- **Dimension:** visual
- **Observed:** re-verify F2 — the demo's "Close friends" badge wraps to two lines at 390 px and the username
  truncates. The badge is host content; the header could keep it on one line.
