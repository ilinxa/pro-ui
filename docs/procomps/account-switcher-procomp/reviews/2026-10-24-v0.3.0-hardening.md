### Rotating dimension

- **Chosen:** real keyboard + focus behaviour in Chromium (focus landing, roving stop, focus return, footer reach).
- **Why:** the whole release is a focus-management change; jsdom cannot show where Radix's auto-focus, the exit
  animation and the browser's focus heuristics actually leave the caret.
- **Verified?** yes — all keyboard invariants held live; it found the narrow-trigger width defect (B1, since 0.1),
  the hover / focus ambiguity (B3) and the Radix focus loop (B5, documented), and characterised the swallowed keys
  during the close animation (R-02).

## Findings (residual, at GATE 3)

U0's 4 extra defects, 14 finder rows (A1–A8, B1–B5; 11 fixed, A7 dropped, B2 / B5 below or documented) are closed in
the loop file. The rows below remain true **after** the fixes.

#### R-01 — Base UI runtime not observed

- **Severity:** 🔸 · **Dimension:** 5
- **Observed:** the docs site and the install consumer run Radix. The width mechanism is proven in a real engine; the
  open-focus fallback for Base UI's initial focus and `dir` / `aria-label` pass-through on Base UI's popup are
  reasoned from the code, not seen.
- **Suggested fix:** observe on the first Base UI consumer, or when an install consumer on a Base UI style exists.

#### R-02 — Keys during the close animation are swallowed

- **Severity:** 🔹 · **Dimension:** 3
- **Observed:** Escape (or a selection) then ↓ within ~100 ms does nothing; Radix returns focus to the trigger after
  the exit animation. Works from ~150 ms.

#### R-03 — Size headroom 1.2 %

- **Severity:** 🔹 · **Dimension:** 9
- **Observed:** 47.41 KB of 48 (estimate 41, +16 % — mostly JSDoc). Any next change needs a budget decision first.

#### R-04 — No type-ahead

- **Severity:** 🔹 · **Dimension:** 3
- **Observed:** APG recommends type-ahead for listboxes; not requested, not implemented (guide §8 says so).
