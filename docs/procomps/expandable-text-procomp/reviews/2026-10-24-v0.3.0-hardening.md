### Rotating dimension

- **Chosen:** real-browser layout (clamp geometry, focus scrolling, bidi).
- **Why:** jsdom has no layout; the component's whole job is layout.
- **Verified?** yes — it found the remaining defect: Chrome scrolls the clipped box to a focused link **before**
  `focus` fires, so "is the link below the clamp?" by geometry alone is always "no" for a Tab (fixed: a scrolled box
  counts as hidden). Also proven live: block children held to 3 lines (the finder's F1, which the unit tests could not
  show), server HTML already clamped, Arabic body right-aligned in an LTR feed.

## Findings (residual, at GATE 3)

The 4 U1 corrections, 9 U4 rows and U5-1 are closed in the loop file (all CONFIRMED; F2 / F5 documented, the rest
fixed and falsified). The rows below remain true **after** the fixes.

#### R-01 — `dir="auto"` follows the first strong character

- **Severity:** 🔸 · **Dimension:** i18n
- **Observed:** a mention-first Arabic post lays out LTR; emoji / number-only bodies are LTR on an RTL page. This is
  the HTML rule the request asked for; the guide gives the `<bdi>` / `dir` workarounds.
- **Suggested fix:** post-card / comment-thread could pass `dir` from the post's language when their loops run.

#### R-02 — Block children cut at a line boundary only with a shared line height

- **Severity:** 🔹 · **Dimension:** layout
- **Observed:** the `N lh` bound uses the container's line height; children with a different line height or margins
  cut mid-line. Browsers without the CSS `lh` unit fall back to the line clamp alone.

#### R-03 — post-card's mention highlighting still cannot be clamped

- **Severity:** 🔹 · **Dimension:** dependents
- **Observed:** `children` makes it possible; `post-card/parts/mention-text.tsx:39-43` still says "v0.3+ may bridge"
  (a version-pinned note in post-card). Wiring belongs to post-card's Part 3 loop.

#### R-04 — Size headroom 4 %

- **Severity:** 🔹 · **Dimension:** 9
- **Observed:** 14.38 KB of 15; the estimate (11.5) was low again — JSDoc + unclamp classes.

#### R-05 — video-player's alias JSDoc is version-pinned (found here, F9)

- **Severity:** 🔹 · **Dimension:** rules
- **Observed:** `video-player/types.ts` "Kept as an alias for one minor" (shipped in 0.3.0).
- **Suggested fix:** reword on video-player's next touch (no version bump for a comment alone).
