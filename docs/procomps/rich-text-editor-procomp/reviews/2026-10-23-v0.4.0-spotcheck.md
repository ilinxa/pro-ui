## What changed

Embeds render through one shared safe-embed module in the editor, the static viewer and the HTML
serializer: `sandbox` (scripts, same-origin, presentation, popups, popups-to-escape-sandbox — never
top-navigation), `referrerPolicy`, `loading="lazy"`, `allow`, `title`; https only; credentials refused;
default host allow-list (YouTube, YouTube-nocookie, Vimeo player). New props `embedAllowList` and
`isEmbedAllowed` on the editor, the viewer and `SerializeHtmlOptions`. A disallowed embed renders as a
plain link card, never an iframe, never dropped. Link `href`s pass `safeHref()` (control chars stripped;
http/https/mailto/tel + relative); the toolbar and floating-toolbar prompts validate; `LinkPlugin` is
configured with `allowedSchemes` in both kits.

## Findings

#### F-01 — embed URL carrying credentials passed the allow-list
- **Severity:** 🔹 · **Location:** `lib/safe-embed.ts` (`resolveEmbed`)
- **Observed:** `https://user:pw@www.youtube.com/...` rendered an iframe.
- **Fix (done):** refused; test "refuses embed URLs carrying credentials".

#### F-02 — render/serializer tests unverified at first finder pass
- **Severity:** 🔸 (verification gap) · **Observed:** vitest worker-start timeouts under host load.
- **Fix (done):** re-run on a quieter host — 35/35, including the serializer honoring `embedAllowList`, which also proves Plate passes `editor` to static renderers.

#### F-03 — policy change on a mounted editor is not reflected until a node re-renders
- **Severity:** 🔹 · **Disposition:** documented in the guide. Follow-up: remount or re-render embeds on policy change — owner: rich-text-editor next loop, target 0.4.x.

#### F-04 — image `src` is not scheme-filtered
- **Severity:** 🔹 · **Observed:** `javascript:` / `data:` in `<img src>` cannot execute script in modern browsers; tracking / mixed content only.
- **Disposition:** follow-up — owner: rich-text-editor next loop, target 0.4.x.

#### F-05 — breadth notes (protocol-relative hrefs, `*.com` wildcards, IDN hosts)
- **Severity:** 🔹 · **Disposition:** documented in the guide security section.
