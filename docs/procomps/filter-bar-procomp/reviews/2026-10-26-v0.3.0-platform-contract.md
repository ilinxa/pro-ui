- **Chosen:** host-integration semantics of the combined `onChange` (the platform filters and fetches in it).
- **Why:** FB1 changes when hosts get called; a wrong merged value means a wrong fetch.
- **Verified?** yes — mount / identity / external-prop = 0 calls, `emitInitialChange` = 1 (also under StrictMode), one
  call per interaction, pending search flushed into the chip / date call (no late call), late-adopting hosts keep the
  typed text; browser: "abc" + chip within ~20 ms → one merged state, nothing after 700 ms.
